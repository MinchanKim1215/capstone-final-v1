# 예측에서 예방 재배치까지

## 기존 V7의 전달값

비행 환경은 0.5초마다 중계기가 실제로 받은 비컨·패킷과 자기 상태에서 48개 관측값, 관측 여부, 9개 이동 의도 항목을 기록한다. 각 중계기와 상대 기체의 최근 40프레임에 지도에서 계산한 46개 기하 특징을 더해 예측기에 넣는다. 추론에는 연결 정답이나 미래 간섭 일정이 들어가지 않는다. [관측 구성](../adaptive_joint_expanded/observation.py#L22)

Transformer는 링크마다 32차원 표현과 다음 지속 단절의 시간 분포를 계산한다. 시간 분포는 0.5초 간격으로 8초를 나눈 16칸과 그 안에 단절 없음 한 칸으로 구성한다. 학습 표지는 현재 연결된 링크에서 다음 단절이 1초 이상 지속되기 시작하는 시점이다. [예측 표지와 확률](../adaptive_joint_expanded/targets.py#L5)

| PPO가 받는 예측 관련 값 | 쓰이는 곳 |
|---|---|
| 상대별 32차원 예측 표현의 유효 링크 평균 | 중계기 행동망의 문맥 |
| 5초 미만, 3~4초, 3~7초, 7초 미만 단절 확률의 링크별 평균·최댓값 | 행동망의 문맥 |
| 수신 근거가 있는 상대 비율 | 문맥에 포함해 관측 범위를 구분 |
| 상대별 5초 미만 위험과 3~7초 위험 | 6초 후보 링크 여유의 개선량에 곱해 후보 점수에 추가 |

위험과 물리 이득이 결합되는 항은 `sum(후보별 링크 여유 개선량 × (5초 미만 위험 + 3~7초 위험)) / (기체 수 - 1)`이다. 여유 개선량은 보정 0 후보 대비 값이다. 위험값의 합계는 3~5초 구간을 두 번 반영하는 후보 가중치다. 여기에 물리 후보 기본 점수와 학습한 PPO 점수를 더하고 불가능한 후보를 마스킹한다. 문맥 80개와 후보별 12개 특징이 행동망에 함께 들어간다. [PPO 점수 계산](../adaptive_joint_expanded/model.py#L56) · [후보별 여유 계산](../adaptive_joint_expanded/features.py#L105)

관측기는 1초마다 `risk_5s`와 `risk_onset_3to7s`를 기록한다. PPO는 3초마다 그 시점까지 받은 관측에서 위험을 다시 계산한다. 현재 연결 상태와 무관하게 유효한 위험값은 후보 점수에 들어간다. 실제 개입 여부는 후보 간 점수 순위에 따라 결정한다. [실행 루프](../adaptive_joint_expanded/rollout.py#L41) · [위험 기록](../adaptive_joint_expanded/world.py#L292)

선택 결과는 중계기별 25개 후보 중 하나다. 후보는 자기 명목 목표에 더할 평면 보정량이다. 목표 보정 범위와 한 주기에 실제로 이동할 수 있는 거리는 다르다. 3초 동안의 실제 이동은 격자 경로, 속도, 기체 간 분리 거리, 장애물 제한을 적용한 뒤 정해진다. 임무 지연이나 공유 단계에서는 이동 보정이 차단될 수 있다. [이동 적용](../adaptive_joint_expanded/world.py#L214) · [기체별 이동](../drone_forecast_joint_training/cooperative/motion.py#L73)

V16의 개선 예측기는 첫 중계기 관측에서 5초와 3~7초의 패킷 서비스 장애 위험을 출력한다. 이전 비교에서는 같은 PPO 궤적의 예측만 평가했다. 한 비행에 대한 서비스 위험 두 값만으로는 어느 중계기를 어디로 옮겨 수색망을 유지할지 비교할 수 없다. [V16 실행 인터페이스](../forecast_causal/runtime.py#L47)

## V17에서 추가한 예방 경로

```mermaid
flowchart LR
    A[실제 수신한 비컨과 첫 중계기의 무선 관측] --> C[후보별 미래 수색망 연결 여유]
    B[기존 PPO의 명령과 가능한 보정 후보] --> C
    C --> D[예상 단절 시점과 대안 경로 비교]
    D --> E[첫 중계기 명령 선택]
    E --> F[기존 안전 이동 엔진]
    F --> G[실제 단절 시작과 지속 시간 기록]
```

추가 예측기는 발행 시각·확정 구간·이동 경로가 든 128바이트 비컨 중 첫 중계기에 실제 도착한 것과 자기 수신 전력·SINR을 사용한다. 수색기 중 하나의 보고가 오래됐거나 최근 무선 관측이 없으면 해당 시점에 기존 PPO를 사용한다. 이번 설계는 별도 수신 슬롯을 할당하지 않고 기존 비컨의 확장 형식을 사용한다. [비컨 디코딩](controller.py#L29) · [비행 루프에서 수신값 전달](runner.py#L75)

후보마다 목표에 이르는 다음 격자 이동을 추정한다. 동료의 마지막 발행 경로와 함께 1~8초의 링크 여유를 계산한다. 각 수색 쌍에서 사용할 수 있는 경로 중 가장 여유가 큰 경로를 찾은 뒤, 수색 쌍 전체에서 가장 취약한 값을 사용한다. 이동 결정에는 후보별 시간에 따른 연결 여유(dB), 현재 여유, 예상 단절 시작, 입력의 수신 근거가 들어간다. 이 비교는 보정된 확률 대신 물리 여유를 점수로 사용한다. [후보 예측과 수색망 여유](controller.py#L109)

이동 결정은 기존 PPO 명령에서 연속 두 미래 표본의 여유가 음수인지 확인한다. 안전 마스크를 통과한 기존 명령, 보정 0, PPO 상위 후보를 비교한다. 대안이 초기 연결을 악화시키지 않고 미래 부족량을 충분히 줄이면 첫 중계기 명령을 바꾼다. 예측상 연결이 이미 나빠진 경우 같은 후보 비교를 복구에도 사용한다. 선행 개입은 1~2초 예측에도 허용했다. 실제로 3초 이상 먼저 개입한 사례는 따로 센다. [명령 선택 규칙](controller.py#L145)

간섭 전환 후보는 실제 수신 전력과 SINR의 차이에서 잡음 추정치를 구한다. 잡음이 −104 dBm 이상이고 최근 두 관측 사이의 상승률이 0.6 dB/s 이상일 때 제한된 잡음 증가를 후보별 미래 여유에 적용한다. 이 문턱은 이번 비교를 위해 정한 값이다. 대기열 증가만 관측되고 미래 단절 신호가 없으면 대기열 감시로 기록한다. 패킷 경로 변경은 별도 실험이다. [관측 기반 전환](controller.py#L70)

후보를 계산할 때 다른 중계기의 다음 실제 행동은 모른다. 각 후보의 추정 궤적과 공동 이동 엔진에서 실현된 궤적의 차이는 결과에서 확인한다. 실제 채널 상태와 미래 기록은 원인 조사 및 검증에만 사용한다. [원인 조사와 요인 제거](diagnostics.py#L31)
