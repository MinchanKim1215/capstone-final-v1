# 단독 Transformer + 공동 PPO 검증 보고서

2026-10-29 · v5 · 실제 실행 기록 · Linux CPU / PyTorch 2.9.1+cpu

**학습 가능한 구현과 재개 경로를 검증했습니다. 현재 수치로 Transformer의 LightGBM 대비 우위나 실기체 사용 가능성을 입증하지는 못했습니다.** 제공 파일은 확대 학습을 시작할 수 있는 코드·체크포인트·검증 데이터입니다. 장시간 본 학습은 사용자 PC에서 실행해야 합니다.

## 변경 내용

학습형 단절 예측기를 Transformer 하나로 통일했습니다. GRU·LSTM·RNN 모듈 및 LightGBM 확률 입력을 사용하지 않습니다. 20초 RF 이력과 현재 알려진 지도·비행 의도를 읽습니다. 기존 물리 후보 생성, 대형 제약, 재배치, RF·패킷 계산과 연속 궤적 감사를 유지했습니다. LightGBM Python 의존성은 이전 모듈 import와 명시적 비교 실험 때문에 남아 있으며 기본 예측·정책에서 트리 모델을 생성하지 않습니다.

예측 출력은 5초 지속 단절 위험, 3~4초·3~7초·0~7초 단절 시작 위험입니다. PPO 업데이트 때 신경망에 의존하는 모든 문맥·후보 이득·점수를 다시 계산해 인코더와 확률 출력층까지 보상이 전달됩니다. 지도 BCE 보조 손실로 예측 의미도 유지합니다.

교수님 의견에 따라 누적 보상 크기를 성능 근거로 삼지 않았습니다. 기존 통신 우선 보상 구조를 유지하고 CTR·PDR·단절 길이·비행 시간·안전 결과로 비교했습니다.

## 실제 실행한 학습·검증

| 항목 | 실제 범위 |
|---|---:|
| 지도학습 훈련 비행 | 24회 |
| 고정 검증 관측 | 8회, 서로 다른 8개 맵 |
| Transformer 지도학습 | 누적 1,200 step, best 1,200 |
| verified_joint | 2 PPO update, 8회 훈련 비행 |
| verified_fixed | 2 PPO update, 8회 훈련 비행 |
| 단위·통합 테스트 | 24개 통과 |
| 기본 경로 검사 | 190개 맵 × 2방향 = 380개 통과 |
| 전체 실행 에피소드 | 100회, 임무 완료 100회, 감사 전부 통과 |
| 최종 테스트 | 32개 맵 / 128조건 비행 미실행 |
| Windows / CUDA / 실기체 | 이 환경에서 실행하지 않음 |

반복 실행·여러 정책의 동일 시나리오가 포함된 에피소드 수입니다. 서로 독립적인 지역 수로 해석하면 안 됩니다. 지도학습 24개 훈련 맵은 전체 훈련 166개 중 일부입니다. 본 학습 스크립트는 이를 192회로 확장합니다. 초기 2 step에서의 AP 0.062는 검증 2회 시점의 값이므로, 현재 8회 검증과의 직접 개선량으로 제시하지 않습니다.

## 단독 예측기: 동일 표본 비교

고정된 physics 기준선 검증 8회에서 같은 관측·시점·정답을 사용했습니다. LightGBM이 유한 값을 출력한 표본으로 두 예측기의 유효 대상을 일치시켰습니다. 정책 실행 결과가 달라지면서 표본이 바뀐 경우와 구분합니다. 아래 Transformer는 PPO 전 1,200 step 사전학습 모델입니다.

| 예측 대상 | 유효 표본 | 양성 비율 | LightGBM AP | Transformer AP | LightGBM Brier | Transformer Brier |
|---|---:|---:|---:|---:|---:|---:|
| 5초 단절 위험 | 161,341 | 1.302% | 0.4736 | 0.2961 | 0.0097 | 0.0107 |
| 3~4초 단절 시작 | 161,341 | 0.398% | 0.1214 | 0.0800 | 0.0040 | 0.0038 |
| 3~7초 단절 시작 | 161,097 | 1.295% | 0.1875 | 0.1314 | 0.0125 | 0.0120 |

**현재 5초 단절 예측 AP는 LightGBM보다 낮습니다.** Transformer에 학습 신호는 확인됐지만 단독 전환이 정확도 향상을 이미 달성했다는 뜻은 아닙니다. 더 많은 맵·비행·학습이 개선을 보장하지 않으므로 확대 학습 후 같은 기준으로 다시 평가해야 합니다. 과거 문서의 AP 0.8064는 다른 지역·.5초 표본·다른 비행 조건의 결과이며 이 표와 비교할 수 없습니다.

사전학습 중에는 검증 비행마다 최대 96개 control 시점을 균등 추출해 best를 선택했습니다. 따라서 그 내부 검증 AP와 위 전체 시점 AP는 표본이 다릅니다. 같은 8회·같은 추출 방식에서의 학습 이력은 다음과 같습니다.

| Step | 5초 위험 AP | 3~7초 시작 AP |
|---:|---:|---:|
| 200 | 0.2975 | 0.1098 |
| 400 | 0.3115 | 0.1549 |
| 600 | 0.3471 | 0.1667 |
| 800 | 0.3496 | 0.1620 |
| 1000 | 0.3478 | 0.1666 |
| 1200 | 0.3588 | 0.1743 |

## 재배치까지 실행한 통신 성능

아래는 동일한 8개 검증 맵·시나리오에서 각 정책을 실제 실행한 결과입니다. 각 학습 실행의 validation best checkpoint를 사용하며 마지막 update가 항상 best는 아닙니다. 선택에 사용한 검증 결과이므로 최종 미사용 테스트 성능으로 부르지 않습니다.

| 정책 | 선택 update | CTR | PDR | 지연 반영 PDR | 최장 단절 | 최대 비행시간 비율 |
|---|---:|---:|---:|---:|---:|---:|
| physics 기준선 | 0 | 97.111% | 98.512% | 96.018% | 35.0s | 1.0036 |
| verified_joint | 1 | 97.543% | 98.827% | 96.366% | 21.5s | 1.0539 |
| verified_fixed | 1 | 97.615% | 98.856% | 96.480% | 21.0s | 1.0599 |

검증 비교의 선택 run은 `verified_fixed`입니다. 물리·시간·PDR 선택 조건 충족 여부는 `True`입니다. 고정 예측기와 공동학습의 우열을 단일 난수·소규모 검증만으로 확정하지 않습니다.

| 기준선 대비 변화 | CTR 변화 (퍼센트포인트) | 지역 단위 bootstrap 95% CI | PDR 변화 (퍼센트포인트) |
|---|---:|---:|---:|
| verified_joint | +0.431 | [-0.189, +1.193] | +0.315 |
| verified_fixed | +0.503 | [-0.368, +1.475] | +0.344 |

CI는 8개 공간 지역을 묶음으로 10,000번 재추출한 탐색적 결과입니다. 같은 지역의 유향 링크·시간 프레임을 독립 표본으로 취급하지 않았습니다. 0을 포함하는 구간에서는 개선이 확실하다고 주장할 수 없습니다.

같은 physics 관측 전체에 고정·공동 모델을 적용한 예측 비교는 `results/transformer/common_corpus_validation.json`에 있습니다. 모델별 비행 경로가 다를 때 예측 AP를 직접 비교하는 문제를 피하기 위한 별도 결과입니다.

## 단절 조기 경보

현재는 축소 8회 pilot이므로 운용 경보를 활성화할 수 없습니다. `AlarmMonitor`가 전체 96회 검증 선택을 요구합니다. 현재 8회에서도 precision·오경보·최소 경보 수의 세 조건을 동시에 만족하는 규칙을 찾지 못했습니다. 아래는 조건 미달 후보 중 recall이 큰 threshold의 진단값이며 운영 승인 수치가 아닙니다. 5초 경보는 onset_3to4s, 8초 경보는 onset_3to7s head를 사용합니다.

| 모델 / 경보 | 최초 경보 precision | 3초 이상 선행 사건 recall | 오경보/드론·시간 | 최초 경보 수 | 조건 충족 후보 |
|---|---:|---:|---:|---:|---|
| verified_joint / 5s | 22.328% | 23.200% | 151.782 | 3892 | False |
| verified_joint / 8s | 28.599% | 41.564% | 146.912 | 4098 | False |
| verified_fixed / 5s | 23.891% | 21.630% | 130.504 | 3428 | False |
| verified_fixed / 8s | 31.763% | 39.212% | 121.000 | 3545 | False |

경보 precision은 해당 horizon 내 사건의 존재 여부입니다. 최소 3초 선행 조건은 별도 사건 recall에 적용하므로, 높은 precision을 높은 조기 탐지율로 해석하면 안 됩니다. 현재 연결 확인·관측 이력 지원 마스크, 21초 warmup, 8초 tail censor, 최소 1초 지속 단절 정의를 적용했습니다.

## 코드 연결·재개 검증

- 미래 정답·중앙 critic 상태를 actor 입력에 넣지 않는지, 히스토리가 미래 RF를 읽지 않는지 검사했습니다.
- 기존 물리·RF·패킷 코드 17개 원본 SHA와 예측기 파일을 보존했습니다. 현재 핵심 소스 150개 SHA가 수집 데이터·체크포인트와 일치합니다.
- `fixed` 예측기의 가중치 변화는 0이며 `joint`에서는 PPO 손실만으로 인코더·확률 출력층 gradient가 모두 0보다 큽니다. auxiliary 손실만의 gradient를 공동학습 근거로 사용하지 않았습니다.
- 별도 압축 해제 폴더에서 전체 파일 검사·24개 테스트·실시간 재생·제공 모델 재개를 다시 통과했습니다. 실제 저장된 지도학습 1,175 step에서 1,200 step까지 25번 재실행한 모델·Adam·샘플러 상태가 원래 결과와 비트 단위로 일치했습니다.
- 모델·Adam·난수 상태를 저장·복구한 CPU 2 update가 중단 없이 실행한 결과와 비트 단위로 일치했습니다. 실제 rollout 중 Ctrl+C로 중단한 별도 run도 이전 commit에서 재개해 update를 완료했습니다.
- 제공 joint/fixed run은 update 1을 별도 프로세스에서 종료한 뒤 update 2로 재개했습니다. stale 행동 log-probability, 파일 손상, 공간 split 누출, 축소 검증에서 테스트·경보 활성화 시도를 차단합니다.
- 공개 StreamingController로 검증 비행 546개 결정을 재생했습니다. 행동 차이 0, 지원 링크 확률 최대 오차 0.0. 이때 LightGBM 생성자와 GRU 생성자를 강제로 차단했습니다.

| 공동학습 update | PPO→encoder gradient norm 최대 | PPO→확률 head gradient norm 최대 | Encoder 변화 L2 | 확률 head 변화 L2 | CPU update 시간 |
|---:|---:|---:|---:|---:|---:|
| 1 | 0.081974 | 0.065815 | 0.038895 | 0.020113 | 299.9s |
| 2 | 0.316757 | 0.283846 | 0.031295 | 0.018362 | 278.6s |

시간은 CPU에서 훈련 비행 4회 수집과 PPO 최대 2 epoch까지 포함하며 정기 검증 시간은 제외합니다. 다른 프로세스를 병행한 환경의 측정값이며 사용자 GPU 시간으로 환산하지 않았습니다.

## 집에서 실행

상세 절차는 `HOME_TRAINING_GUIDE.md`를 따르세요. Windows NVIDIA에서는 새 폴더에 완전히 압축을 풀고 다음 순서입니다.

```bat
01_setup_nvidia.bat
02_train_transformer.bat 256 4
```

01번은 대상 PC의 실제 CUDA 역전파·CPU 수집과의 행동 확률 일치·GPU checkpoint/Adam 재개를 검사하고 실패 시 중단합니다. 이 환경에서는 동일 검사 경로의 CPU 실행을 확인했습니다. Windows/CUDA 성공을 미리 보장하지 않습니다.

02번은 훈련 수집 192회, 사전학습 누적 3,000 step, 새 `transformer_main` 공동 PPO 누적 256 update, 전체 검증 선택을 차례로 실행합니다. 조기 중단 조건에 따라 목표 전 종료될 수 있습니다. 제공 `verified_joint`를 그대로 잇는 03번은 작은 검증 설정이므로 본 학습에는 02번을 권장합니다.

실기체 센서 드라이버, 명령 전달·비상정지 연동, 실측 RF 보정과 실제 위치 오차·풍속 검증은 별도로 필요합니다. 현재 결과는 시뮬레이션 안에서의 결과입니다.

원시 수치: `docs/transformer_results.json`, `results/transformer/paired_validation.json`, `results/transformer/verification/`. 과거 기록은 `docs/v4_results.json`과 `docs/prediction_alarm_metrics.*`로 분리했습니다.
