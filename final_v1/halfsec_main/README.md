# Final V1 기본 0.5초 제어

11월 24일 제출용 기본 실행을 `halfsec_planned_eight`로 전환했다. 수색기 3대와 중계기 5대로 임무를 수행한다. 11월 13일 지도 확장 공동학습에서 고정한 30회차 Transformer·전체망 위험 모델·PPO 가중치를 사용한다. 판단 주기와 무선 판정 주기는 0.5초, 비콘 송신 주기는 1초, 운동 계산 주기는 0.1초다. 수평 재배치 명령은 계획 계산 0.2초와 전송 0.1초를 거친다.

## 비행 전 배치와 구간 통과

- 건물 높이와 전체 수색 경로에서 예상되는 전파 여유를 평가한다. 수색 지점을 유지하면서 기존 중계기 한 대의 고정 위치와 다른 한 대의 구간별 상승을 시험한다. 배치 점검 결과에 따라 두 조치를 결합하거나 일부를 적용하고, 적합한 후보가 없으면 기본 대형을 사용한다.
- 고정 중계기는 지정 위치에 배치된 상태로 시작한다. 고도 담당 중계기는 차폐 구간에 앞서 55~80m의 선택 고도로 오른다. 최근 무선 응답과 수색기 간 패킷 도착을 확인하고 진입한다. 정해진 시간 내 확인이 끝나지 않으면 기존 항법으로 진행하며 해당 구간을 기록한다.
- 통과 후 5m씩 하강하며 연결을 확인한다. 하강 확인이 끝나기 전에 새 상승 구간이 시작되어도 이전 확인을 마치거나 직전 안전 고도로 복귀한 뒤 새 상승을 요청한다.

## 예측과 재배치

- 3초 이상 7초 미만의 단절 위험에는 Transformer 기반 전체망 점수 75%, LightGBM 17.5%, 물리 점수 7.5%를 사용한다. PPO는 수색 진행·통로·임박 단절 위험을 검사한 후보를 평가한다.
- 최근 받은 비콘의 시각으로 수색기 관측 공백을 계산한다. 누락 기준 3초에 비콘 주기 한 번을 더하고, 현재 궤적에서 1초 이상 단절을 예측하는 경우 보수적인 통신 여유로 복구 후보를 다시 검사한다. 이미 연결된 수색 경로를 보호하고, 더 빠른 안정 재연결이나 줄어든 통신 여유 부족분을 요구한다.
- 수색 지점이 20초간 진행되지 않으면 항법이 다음 지점으로 가는 경로를 찾는다. 예약된 이동을 끝낸 뒤 안전 간선으로 한 대씩 통과하거나 중계기를 옆 노드에 세워 통로를 비운다. 이 과정에서는 추가 재배치 요청을 멈춘다. 수색 지점은 실제 도달 시에만 갱신한다.

## 실행

프로젝트 루트에서 팀이 사용하던 Python 환경과 지도·V7·LightGBM 자료를 사용한다. `checkpoint.pt`와 `checkpoint.json`은 이 폴더에 함께 둔다.

```powershell
& .\drone_forecast_joint_training\.venv\Scripts\python.exe -B -m final_v1.fly --steps 48
```

`--steps 48`은 사전 배치를 계산한 뒤 24초 확인 비행을 수행한다. 인자를 생략하면 전체 임무를 실행한다. `--region`, `--direction`, `--kind`, `--seed`로 지도와 조건을 선택한다. 결과에는 실제 편대 규모, 고정 중계 위치, 예정 고도 구간, 확인 후 통과 횟수, 마지막 고도와 완주·통신 지표가 담긴다.

`--controller v21_transformer_halfsec`는 11월 22일의 0.5초 비교 방식이다. `--controller v21_transformer`는 기존 3초 비교 방식이다. `--command-loss`는 선택된 제어 방식에 명령 미수신 시험을 추가한다.
