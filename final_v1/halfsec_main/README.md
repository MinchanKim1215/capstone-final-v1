# Final V1 기본 0.5초 제어

11월 22일 기본 실행을 `v21_transformer_halfsec`으로 전환했다. 단절 감소를 우선하도록 11월 13일 지도 확장 공동학습에서 고정한 30회차 Transformer·전체망 위험 모델·PPO 가중치를 사용한다. 판단 주기 0.5초, 비콘 송신 주기 1초, 무선 판정 주기 0.5초, 운동 계산 주기 0.1초다. 명령은 계획 계산 0.2초와 전송 0.1초를 거친다.

## 예측과 재배치

- 3초 이상 7초 미만의 단절 위험에는 Transformer 기반 전체망 점수 75%, LightGBM 17.5%, 물리 점수 7.5%를 사용한다. PPO는 수색 진행·통로·임박 단절 위험을 검사한 후보를 평가한다.
- 최근 받은 비콘의 시각으로 수색기 관측 공백을 계산한다. 누락 기준 3초에 비콘 주기 한 번을 더하고, 현재 궤적에서 1초 이상 단절을 예측하는 경우 보수적인 통신 여유로 복구 후보를 다시 검사한다. 이미 연결된 수색 경로를 보호하고, 더 빠른 안정 재연결이나 줄어든 통신 여유 부족분을 요구한다.
- 수색 지점이 20초간 진행되지 않으면 항법이 다음 지점으로 가는 경로를 찾는다. 예약된 이동을 끝낸 뒤 안전 간선으로 한 대씩 통과하거나 중계기를 옆 노드에 세워 통로를 비운다. 이 과정에서는 추가 재배치 요청을 멈춘다. 수색 지점은 실제 도달 시에만 갱신한다.

## 실행

프로젝트 루트에서 팀이 사용하던 Python 환경과 지도·V7·LightGBM 자료를 사용한다. `checkpoint.pt`와 `checkpoint.json`은 이 폴더에 함께 둔다.

```powershell
& .\drone_forecast_joint_training\.venv\Scripts\python.exe -B -m final_v1.fly --steps 48
```

`--steps 48`은 기본 제어의 24초 확인 비행이다. 인자를 생략하면 전체 임무를 실행한다. `--controller v21_transformer`는 기존 3초 비교 방식이다. `--command-loss`는 선택된 제어 방식에 명령 미수신 시험을 추가한다.

기존 팀 ZIP에는 이 폴더 전체와 `final_v1/fly.py`, `final_v1/relocation.py`를 같은 경로로 복사한다. 기존 Python 환경으로 `code/`에서 `python -B run_latest_final_v1.py --steps 48`을 실행한다. 기본 예제는 팀 ZIP에 포함된 광주 지도다. 지도 200곳을 추가 등록한 작업 환경에서는 해당 지도도 사용할 수 있다.

## 11월 22일 비행 검증

| 별도 지도 8곳 | 기존 3초 | 기본 0.5초 |
|---|---:|---:|
| 새 단절 | 26건 | 20건 |
| 시간당 새 단절 | 6.25회 | 3.35회 |
| 누적 단절 시간 | 178.5초 | 178.5초 |

기존 0.5초 모델이 시간 제한에 도달한 6조건을 다시 실행했다. 부산 세 조건과 인천 한 조건이 완주했다. 인천의 무간섭·간헐 간섭 조건은 785개 중 703개 지점에서 7,200초 제한에 도달했다. 평가한 새 코드의 14비행은 모두 안전 검사와 패킷 보존 검사를 통과했다. 별도 지도 비교에서 시간당 새 단절 변화의 95% 구간은 −6.55~+1.86회였다.
