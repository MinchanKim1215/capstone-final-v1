**단절 예측 기술과 신뢰도 향상 계획**

기준: 2026-10-29, 현재 v5 소스와 176 update 검증 기록. 이 문서는 분석·개선 제안이다. 진행 중인 학습, 보상, 소스, 체크포인트를 변경하지 않았다. 아래 개선안의 효과를 이 프로젝트에서 검증한 것은 아니다.

현재 Transformer에는 단절 위험을 구분하는 신호가 있다. 176 update에서 5초 위험 AUROC는 0.9415, AP는 0.5081이다. 그러나 확률 0.5에서 해당 위험 재현율은 31.63%이고, 사건 기반 8초 경보의 3초 이상 선행 재현율은 0.42%다. 사람이 신뢰할 예측을 위해서는 순위, 실제 경보의 정밀도·사건 재현율, 선행시간, 오경보, 확률 보정, 지역 일반화를 함께 개선하고 확인해야 한다.

**현재 구현한 기술**

| 구성 | 실제 구현 | 역할과 한계 |
| --- | --- | --- |
| 통신·이동 관측 | 링크별 0.5초 관측 40개, 약 20초 이력. 관측값 48개 + 마스크 48개 + 알려진 비행 의도 9개 = 시점당 105차원 | 신호·간섭 대비 품질, 비콘 수신·정보 나이, 상대 위치·속도 등의 과거 흐름을 사용한다. 관측되지 않은 미래 간섭을 정답처럼 입력하지 않는다. |
| 입력 전처리 | 물리량별 스케일링, 범위 제한, 결측 마스크, 저장 float16 / 신경망 계산 float32 | 단위 차이와 결측을 다룬다. 센서가 실제로 측정하지 않은 정보를 복원했다는 의미는 아니다. |
| Transformer | hidden 32, attention head 4개, encoder 2층, feed-forward 64, 위치 인코딩, dropout 0 | 20초 이력에서 관련 시점의 패턴을 결합한다. 과거 window 내부를 보는 모델이며, 미래 관측을 입력으로 사용하지 않는다. dropout 0은 PPO 수집·재평가 일치를 위한 현재 설계다. |
| 지도·물리 특징 | 현재 위치·속도·수신된 목표를 외삽하고 건물 지도와 전파 계산으로 만든 46차원 특징 | 0.5~8초의 13개 시점에서 경로손실 변화, LoS, 통신 여유 등을 계산한다. 실제 미래 위치나 미래 재머 상태를 조회하지 않는다. |
| 다중 예측 출력 | 5초 지속 단절 위험, 3~4초·3~7초·0~7초 단절 시작 위험 | 단절 여부와 단절 시작을 구분한다. 실제 시간 구간은 0.5초 이산 라벨 정의를 따른다. |
| 확률 포함 관계 | p34 ≤ p5, p34 ≤ p37, p5 ≤ p07, p37 ≤ p07을 구조적으로 강제 | 사건 포함 관계에 어긋나는 확률을 막는다. 확률 보정이나 정확성을 자동으로 보장하지는 않는다. |
| 지도학습 | BCE, head 가중치 [1,2,2,1], 양성/음성 추출과 importance 보정, Adam | 희귀 양성을 배치에서 보면서 원래 발생 비율을 보정한다. 현재 추출의 양성 정의는 risk_5s 기준이며, 다른 시작 head별·사건별 균형 추출은 아니다. |
| 공동 PPO | 재배치 정책, Transformer encoder·확률 head를 함께 조정. PPO 목적에 예측 BCE 보조 손실 계수 0.1을 결합 | 제어에 도움이 되는 표현과 예측을 함께 학습한다. 정책 gradient가 실제 예측기에 전달되는 것은 검사했지만, 예측 정확도가 항상 좋아진다는 보장은 없다. |
| 경보 규칙 | 검증 확률 quantile·고정 임계값, 진입/해제 임계값 차이를 이용한 hysteresis | 단발 분류와 사건 경보를 구분한다. 176의 평가에서는 408개 후보 조합을 탐색했다. 임계값과 hysteresis가 아예 없는 코드가 아니다. |
| 데이터·실험 계약 | 공간 그룹 분리, 미래 정답 입력 차단, 체크포인트/데이터 SHA, 마스크·지원 범위, 고정 검증과 미사용 테스트 분리 | 데이터 누출과 잘못된 재개를 막는다. 시뮬레이션 가정 밖의 실제 RF 환경까지 검증한 것은 아니다. |

유일한 학습형 예측기는 Transformer다. GRU나 LightGBM 점수를 기본 예측기의 입력으로 사용하지 않는다. 여러 드론을 제어하지만 현재 예측기는 링크별 이력을 처리하며, GNN 기반 예측기를 구현한 것은 아니다.

**예측 품질 관점에서 확인된 설계 차이**

사전학습 best는 0.6 × AP(risk_5s) + 0.4 × AP(onset_3to7s)로 선택한다. 공동 PPO best는 안전·완료·비행 시간 조건을 통과한 후보 중 연결 유지율, PDR, 최장 단절 순서로 선택한다. 따라서 제어 best를 예측 best로 부를 수 없다. PPO 단계의 선택에는 사건 재현율이나 확률 보정 성능이 직접 들어가지 않는다.

PPO가 예측기를 제어에 유리한 방향으로 바꾸면서 예측 자체에는 불리할 가능성은 있다. 하지만 이것이 지금 성능 한계의 원인이라고 아직 측정하지 않았다. 0.1이라는 보조 손실 계수를 보고 '예측을 10%만 학습한다'고 해석해서도 안 된다. 목적별 loss와 gradient 크기·방향을 측정해야 한다.

현재 경보 후보의 통과 조건은 정밀도 ≥80%, 오경보 ≤5회/드론·시간, 최초 경보 ≥10건이다. 최소 사건 재현율 조건이 없어 단절 대부분을 놓치는 후보도 통과할 수 있다. 176 update의 8초 후보가 그 사례다. 전체 검증을 요구하는 실제 AlarmMonitor의 추가 제한은 별도로 존재한다.

**성능 향상을 위한 실행 우선순위**

1. **예측의 의미와 합격 기준부터 고정한다.** 실제 현재 정책하의 단절 위험인지, 재배치하지 않았을 때의 위험인지 구분한다. 현 정답은 실제 비행 결과다. 예측을 보고 회피한 뒤 단절이 발생하지 않은 사례는 평가 해석이 달라질 수 있다. 이것을 현재 오경보의 원인으로 단정하지 말고, 고정 정책별 평가와 필요시 통제된 반사실 시뮬레이션으로 확인한다.

2. **같은 관측에서 예측기들을 비교한다.** 보존된 사전학습 best, PPO 176, 최종 공동학습 모델을 동일 공개 관측·시점·지원 마스크·정답에 적용한다. 지도별 AP, Brier, 정밀도–재현율 곡선, 경보 오경보 제한에서의 사건 재현율, 사건 전 10/8/5/3/1초 점수 추이를 비교한다. 현재 176 정책 경로의 AP와 다른 경로의 AP를 직접 비교해 공동학습 효과를 주장하지 않는다.

3. **사건과 조건을 기준으로 데이터 부족을 측정한다.** 별도 사전학습 corpus는 192회이고 PPO 경험은 추가로 쌓이는 중이다. '비행 수 192개뿐'이 전체 학습 경험을 뜻하지는 않는다. 훈련 166개 지역의 방향·간섭 조합, 단절 전조, 건물 모서리, 정보 노후화, 재머 시작·종료, 실제 오경보 조건별 사건 수를 점검한다. 필요한 조건과 seed를 훈련 지역에서 보강하고 정책별 데이터 분포를 명시한다.

4. **head별·사건별 학습을 검토한다.** 현재도 양성 추출과 보정이 있다. 이를 없다고 가정하지 않는다. risk_5s 양성만으로 배치를 구성하는 것과 별개로 onset_3to4s/onset_3to7s 양성, 놓친 사건, 어려운 정상 사례의 기여를 점검한다. 같은 긴 단절의 인접 프레임만 반복해서 학습하지 않도록 사건 단위 추출을 검토한다. 가중 BCE 등의 변경은 정밀도·재현율·보정 효과를 함께 비교하는 새 실험으로 다룬다. 단순 가중치 증가는 오경보를 늘릴 수 있다.

5. **예측 품질을 보호하면서 제어와 결합한다.** 동일한 사전학습 모델에서 예측기를 고정한 PPO와 공동 PPO를 맞춰 비교한다. 공동학습의 예측 성능 하락이 확인되면 예측 BCE의 상대 영향, encoder 학습률, 예측 추가 학습 단계, 제어용 adapter와 예측용 출력 경로 분리를 실험한다. gradient 충돌이 확인될 때만 gradient 제어 기법을 검토한다. 통신 성능만 좋은 모델과 예측 성능이 좋은 모델을 각각 보관하고, 최종 선택에는 양쪽 조건을 명시한다.

6. **확률을 보정하고 경보를 별도로 검증한다.** reliability diagram과 Brier 등을 사용해 예측 확률과 실제 발생률이 맞는지 확인한다. 필요하면 별도의 공간 그룹 보정 데이터로 temperature/Platt 등의 보정을 비교한다. 현재 출력의 사건 포함 관계가 유지되는지도 검사한다. 보정은 확률 해석을 개선하는 절차이며, 놓친 전조를 만들거나 AP·가능한 정밀도–재현율 범위를 자동으로 높이는 방법이 아니다. 이미 수행 중인 임계값 탐색과 구분한다. 연속 확인을 추가하면 3초 제어 주기만큼 경보가 늦어질 수 있어 선행시간을 다시 평가한다.

7. **입력과 모델 크기는 진단 후 변경한다.** 예측 시점에 실제 알 수 있는 통신 여유의 변화, 비콘 정보 나이, 링크 방향성, 지도 차폐, 비행 의도의 유효성부터 점검한다. 지금도 이 중 여러 정보가 이미 들어 있다. 정보가 충분한데도 학습 성능이 제한되는지 확인한 다음 hidden 64 등 제한된 Transformer 크기·과거 길이를 비교한다. 최신 큰 모델로 교체하거나 layer만 늘리는 것을 첫 해결책으로 삼지 않는다.

8. **신뢰할 수 없는 입력에서는 판단 불가를 표시한다.** 오래된 비콘, 부족한 이력, 학습 범위를 벗어난 간섭·지도·속도를 정상/저위험으로 조용히 처리하지 않는다. 지원 범위와 판단 불가 비율을 표시하고 물리 기반 제어로 연결한다. 판단을 유보한 사건을 평가에서 몰래 제거하면 안 된다. 이런 처리는 확률값이 낮다는 이유만으로 구현되는 정식 불확실성 추정과 동일하지 않다.

9. **평가와 튜닝을 분리한다.** 검증 지역의 모델 선택과 보정/경보 튜닝을 공간 그룹으로 분리하거나 교차 적합을 사용한다. 여러 학습 seed에서 성능과 실패 지역을 확인하고 전체 96조건으로 비교한다. 최종 테스트는 개발을 마친 뒤 고정한 설정으로 한 번 평가한다. 현재 run의 소스/분할/해시를 바꿔 재개하지 않고 새 실험으로 기록한다.

**사람이 신뢰할 예측의 개발 목표 예시**

다음 숫자는 교수 지정값이나 이미 달성한 성능이 아니라, 요구사항을 구체화하기 위한 제안이다. 환경의 관측 가능성과 대응 시간에 맞춰 타당성을 검토해야 한다.

| 항목 | 예시 개발 목표 |
| --- | --- |
| 최초 경보 정밀도 | 90% 이상 |
| 최소 3초 선행 사건 재현율 | 80% 이상 |
| 오경보 | 1회/드론·시간 이하 |
| 예측 확률 신뢰성 | 신뢰도 도표·Brier 등으로 실제 발생률과의 일치 확인 |
| 적용 범위 | 지역·간섭 조건별 성능과 판단 불가 비율 공개 |

어떤 임계값에서도 정밀도·사건 재현율·오경보 조건을 동시에 만족하지 못하면 '신뢰 가능'으로 표시하지 않는다. 눈에 보이는 전조 없이 무작위로 시작하는 간섭 등은 현재 관측만으로 충분히 미리 예측하기 어려울 수 있으며, 이런 조건까지 예측 성공을 보장할 수 없다.
